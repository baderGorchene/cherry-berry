# Phase 2 — Editor Core Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A person creates a design from Home (preset or custom size), edits it on a canvas — basic shapes and text, select/move/resize/rotate, layers, pages, properties, undo/redo — and every change autosaves to the server.

**Architecture:** The design lives in a Yjs document whose layout mirrors the `.cherry` schema; `@cherry/doc` owns the Yjs binding, all editing operations and the undo manager, so the web app never mutates Yjs directly. The server stores each design's Yjs state (bytea) and *merges* every save into it (CRDT merge, validated against the `.cherry` schema), which makes two open tabs safe today and is the persistence Phase 6's Hocuspocus will reuse. The web editor renders with react-konva; panels (layers, pages, properties) are plain DOM bound to the same Y.Doc.

**Tech Stack:** yjs, konva + react-konva (all MIT), plus Phase 1's stack.

**Spec:** `docs/superpowers/specs/2026-11-11-cherry-berry-design.md` (Phase 2 line). Builds on Phase 1 (`docs/superpowers/plans/2026-11-11-01-foundation.md`), committed on `main`.

## Global Constraints

- Everything in Phase 1's Global Constraints still applies (MIT-compatible deps only, palette and text-contrast rules, fonts, `/api` routes, `{ "error": "<code>" }` bodies, Windows-safe scripts).
- No user-facing AI features. No logo: the product name is plain text.
- Geometry units: node `x/y/width/height` and page `bleed` are in the page's `unit`. `fontSize` is in points for every unit. Conversions: `px` 1, `mm` 96/25.4, `in` 96 px per unit; 1 pt = 96/72 px.
- Rotation: degrees clockwise around the node's box center; `x/y` is the top-left of the unrotated box.
- Child order in any `nodes`/`children` array is bottom → top (last item is drawn on top).
- Yjs transaction origins: `LOCAL = "local"` for this client's edits, `REMOTE = "remote"` for merged server state. Only `LOCAL` is undoable.
- Roles: `owner`/`admin`/`editor` can edit designs; `viewer` is read-only. Non-members get `404 not_found` (never reveal a design exists).
- Basic shapes in this phase: rectangle, ellipse, triangle, line, star, arrow. Fonts offered: Inter, Space Grotesk, Georgia, Arial, Times New Roman, Courier New. Images render as a placeholder box until Phase 4.

## Review Focus

1. Network drops or the server errors mid-edit → status reads "Offline — retrying", saves retry with backoff, nothing is lost; closing the tab with unsaved changes asks for confirmation. (Task 5)
2. The same design open in two tabs (or by two people) → each save merges; neither tab's edits are overwritten. (Task 4)
3. A viewer opens a design → canvas and panels are read-only, and a forged save gets `403 forbidden`. (Tasks 4, 6)
4. Undo after the server merged someone else's changes → undoes only your own edits. (Task 2)
5. A save carrying garbage or a schema-invalid document → `400 invalid_document`, stored design untouched; a design that fails to load shows "This design couldn't be opened." instead of a blank or crashed page. (Tasks 4, 6)
