# Instance Admin & Print Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give the people who run a Cherry Berry server an Instance admin area (overview, sign-in & registration policy, users & workspaces with suspension, storage, a moderation queue for public content), and add an optional print service that turns exports into CMYK PDF/X and colour plates.

**Architecture:** Instance admins are named by the `ADMIN_EMAILS` env var. Instance-wide settings live in a one-row `instance_settings` table, and the server enforces them: Better Auth database hooks for sign-up and suspension, the workspace route, and the upload route. Everything lives under `/api/admin/*` and a new `/admin` web route. Print runs as a separate optional container (`apps/print`), a tiny dependency-free Node HTTP server that shells out to the Ghostscript CLI (AGPL, never linked). The main server talks to it over HTTP when `PRINT_URL` is set, and adds two export formats: `pdf-x` and `plates`.

**Tech Stack:** Fastify 5, Drizzle (PostgreSQL / PGlite), Better Auth database hooks, React 19, Vitest, Playwright, Node 22 `node:http` + `node:child_process`, Ghostscript (container only), fflate (already installed) for the plates zip.

**Spec:** `docs/superpowers/specs/2026-11-11-cherry-berry-design.md` (Phase 9: "Instance admin & print — registration policy, storage, moderation queue; optional print service (CMYK, ICC, spot plates)"). Screen: `InstanceAdmin` in the screen designs (sections Overview, Moderation, Users & workspaces, Storage, Sign-in & registration).

## Global Constraints

- Every dependency is MIT, Apache-2.0, BSD, ISC or MPL-2.0. Ghostscript is **AGPL**, so it runs only in the separate optional print container and is called as a CLI process. No MIT package imports it, and `apps/print` has zero npm dependencies.
- No AI features. No logo. No mascot.
- Text colour contrast is at least 4.5:1. `#8E1EA2` is the only palette colour for body text on white; `#C654C3` is for large text and icons only; `#ED96D7` and `#FFC0DE` are backgrounds only. Neutrals: ink `#22142A`, muted `#5D4E66`, line `#E9DFEC`, surface `#FBF7FC`. Status: success `#1E7A46`, warning `#B45309`, error `#B3261E`.
- Fonts: Space Grotesk for headings, Inter for body.
- Touch targets are at least 44 px. Phone breakpoint: `max-width: 759px`. Desktop layouts of existing pages stay unchanged.
- Server routes (`*/routes.ts`) do auth plus Zod parsing only. Logic and queries go in `*/service.ts`. Errors are `HttpError` and map to `{ error: code }`.
- Migrations come only from `pnpm --filter @cherry/server exec drizzle-kit generate`. Never hand-edit SQL, snapshots or `pnpm-lock.yaml`.
- E2E uses ports 3101/5181 only. Never touch 3000/5173.
- The server makes no outbound requests other than to `PRINT_URL` and S3. In particular, it has no update check.

## Decisions (made here, binding on tasks)

1. **Who is an instance admin.** An instance admin is any signed-in user whose email, lowercased, is in `ADMIN_EMAILS` (comma-separated, trimmed, lowercased; empty means no admins). It is not stored in the DB, so a self-hoster can always recover access by editing env. Admins can't be suspended.
2. **Settings row.** `instance_settings` has exactly one row (`id = 1`, enforced by a check). Columns and defaults:
   - `registration` in `('open','invited','domains')`, default `'open'`.
   - `allowed_domains text[]`, default `'{}'`.
   - `workspace_creation` in `('anyone','admins')`, default `'anyone'`.
   - `max_upload_mb` in `(20,50,100)`, default `50`, matching today's 50 MB.
   - `storage_quota_gb integer null`, where null means unlimited; when set, it is at least 1.
   - A missing row reads as the defaults; the first save upserts it.
3. **Registration.**
   - `invited` admits an email that has an invitation with `accepted_at is null` and `expires_at > now()`.
   - `domains` admits an email whose part after the last `@`, lowercased, equals one of `allowed_domains` exactly. Subdomains are not included.
   - Admin emails are always admitted.
   - A refusal is a 403 with `{ error: "registration_closed" }` (the code in Better Auth's error body).
   - The policy never affects existing accounts signing in.
4. **Suspension.**
   - It sets `user.suspended_at` (a new nullable column; Better Auth ignores it) and deletes all of that user's sessions.
   - A `session.create.before` hook refuses suspended users with 403 `{ error: "suspended" }`.
   - Content is not touched; removal is a separate moderation action.
   - Live collab sockets of a suspended user are closed through the existing `collab` handle if it exposes one. Otherwise they close on the next reconnect (it has no session). The task records which.
5. **Storage used** is `sum(assets.bytes)` of non-deleted assets plus `sum` of brand font file bytes (whatever byte column `brand_fonts` has). When `storage_quota_gb` is set, an upload that would exceed it gets 507 `storage_full`. Fonts count but aren't blocked, so a full server can still fix brand kits.
6. **Upload limit.** The multipart limit becomes 100 MB, the largest allowed setting. After reading, a file over `max_upload_mb` gets 413 `too_large`, the code the upload route already uses.
7. **Moderation queue** (instance-wide; the existing per-workspace queue stays). Two kinds of rows:
   - **`report`:** targets with open reports whose target is **public** (assets, shapes, templates), one row per target, newest first, with the count. Actions:
     - `keep` sets all open reports on the target to `dismissed`.
     - `remove` reuses the existing remove paths: `deleteAsset`, `deleteShape`, and unpublish (delete) for templates. It sets the reports to `removed`.
     - `suspend` does `remove`, then suspends the uploader (Decision 4). It is refused with 400 `invalid_body` when the uploader is an admin.
   - **`sanitized`:** public SVG assets whose upload had something stripped by the sanitizer (`assets.sanitized = true`) and `assets.reviewed_at is null`. Actions:
     - `approve` sets `reviewed_at`.
     - `remove` deletes the asset.
   - The 3-report auto-hide rule (`reports/hide.ts`) stays as the safety net until an admin acts. `keep` unhides because it dismisses the reports.
   - "Missing attribution" detection from the mock is **not built**. Template attribution is already required by DB checks, and auto-detecting uncredited CC-BY use inside designs is a separate feature.
8. **Overview** shows the version (`apps/server/package.json` `version`), the database (`PostgreSQL` or `PGlite` from the driver in use), file storage (`S3-compatible bucket` or `In memory (testing)`), storage used / quota, and counts of users, workspaces, designs and open queue items. The mock's "Up to date" badge is **not built** (no outbound update check).
9. **Print service contract** (`apps/print`, default port 8080):
   - `GET /health` returns `{ status: "ok", gs: "<gs --version>" }`.
   - `POST /pdfx`: the body is an RGB PDF (`application/pdf`, at most 200 MB). It returns a CMYK PDF/X-3 converted with the output ICC profile: `PRINT_ICC_PROFILE` (a path inside the container) or Ghostscript's bundled default CMYK profile. Spot colours are kept as Separation colourspaces if the input has them; Cherry Berry documents currently produce none.
   - `POST /plates?dpi=150`: the same body. It returns `application/json` `{ plates: [{ page: number, name: "Cyan" | "Magenta" | "Yellow" | "Black" | <spot name>, png: <base64> }] }`, one greyscale PNG per separation per page, via Ghostscript's `tiffsep`-family separation output converted to PNG inside gs (`png` separations or `tiffsep` + gs re-render, the implementer's choice). `dpi` is in `72..300`.
   - One Ghostscript job runs at a time. A second concurrent request waits; more than 4 waiting get 429 `busy`.
   - Each job is killed after 120 s, giving 504 `timeout`. Bad input gives 422 `gs_failed`.
   - Temp files go in a per-job directory under `os.tmpdir()` and are always removed.
   - "Spot plates" in the spec is met by plate output that includes any spot separations. Adding spot swatches to the `.cherry` document model is **out of scope** (a document-format change), and the preflight copy says so.
10. **Server print formats.**
    - `PRINT_URL` (optional URL) enables export formats `pdf-x` (the existing `pdf-print` output, with bleed and crop marks, sent to `/pdfx`) and `plates` (the `pdf-print` output sent to `/plates`, zipped with fflate as `<title>-plates.zip`, files named `p<page>-<name>.png`).
    - Without `PRINT_URL` those formats give 400 `invalid_body`.
    - An unreachable service, or one that errors or times out, gives 503 `print_unavailable` (server-side timeout 130 s). They count toward the existing `MAX_EXPORTS` concurrency.
    - `GET /api/designs/:id/export/info` gains `print: boolean`.
    - The preflight `color` check:
      - **with print:** CMYK pages → `pass`, "Converted to CMYK with the print service".
      - **without print:** the copy is unchanged except it says "CMYK and PDF/X come with the print service; spot swatches aren't supported yet."
11. **Web.**
    - `/admin` is reachable only by admins. Non-admins are redirected to `/`.
    - An "Instance admin" item appears in the account menu when `GET /api/instance` says `admin: true`.
    - `GET /api/instance` returns `{ admin: boolean, canCreateWorkspace: boolean, maxUploadMb: number }` for any signed-in user.
    - The Workspaces page hides "Create workspace" when `canCreateWorkspace` is false.
    - The upload dialog shows "Up to {maxUploadMb} MB".
    - The sign-up error `registration_closed` reads "This server isn't taking new sign-ups. Ask an admin to invite you."
    - `suspended` on sign-in reads "This account is suspended. Contact the server's admin."

## Review Focus

1. **Locking yourself out.** An admin suspends themselves or another admin, or sets registration to `invited` with no invitations. Expected: suspending an admin is refused (400 `invalid_body`), and admins can always sign up and sign in whatever the policy. Test in Task 2: `admins cannot be suspended`; in Task 1: `admin email signs up under any policy`.
2. **Sloppy registration inputs.** `Bob@Acme.com` under domain `acme.com`; `x@evil-acme.com`; `x@acme.com.evil.io`; `x@sub.acme.com`; an expired or accepted invitation; domains typed as ` @Acme.COM ` in settings. Expected: case-insensitive exact match; settings normalise domains (trim, strip a leading `@`, lowercase, dedupe, reject anything without a dot with 400). Test in Task 1: `domain policy matches exactly` and `invited policy needs a live invitation`.
3. **A suspended user with a tab open.** Their next API call gets 401, their next sign-in gets 403 `suspended`, and unsuspending lets them sign in again. Test in Task 2: `suspension ends sessions and blocks sign-in`.
4. **The print service is down, slow or returns junk.** The export fails within the timeout with "The print service isn't reachable right now" (503 `print_unavailable`). Other formats keep working, and the concurrency slot is released. Test in Task 6: `print service down gives print_unavailable and frees the slot`.
5. **Removing reported content that other designs use.** The removed asset disappears from the library, the queue and search. Designs that placed it still open and export, showing the existing missing-asset placeholder. Test in Task 3: `removed asset still lets designs export`.
