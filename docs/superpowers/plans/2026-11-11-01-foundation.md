# Phase 1 — Foundation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A running Cherry Berry skeleton: open `.cherry` document format, a server with accounts and workspaces (invite / ID + password / open), Docker Compose for Postgres + MinIO, and a web shell where a person signs up, creates or joins a workspace, and lands on Home.

**Architecture:** pnpm monorepo. `packages/doc` holds the `.cherry` schema and I/O, shared by every app. `apps/server` is a Fastify app built by a `buildApp(config)` factory (so tests use `app.inject`), with Better Auth for users/sessions and Cherry Berry's own Drizzle tables for workspaces. `apps/web` is a React + Vite app calling the server over `/api`.

**Tech Stack:** TypeScript, pnpm workspaces, Vitest, zod, Fastify, @fastify/rate-limit, Drizzle ORM + node-postgres, Better Auth, @node-rs/argon2, React, React Router, Vite, Playwright, Docker Compose (postgres, minio).

**Spec:** `docs/superpowers/specs/2026-11-11-cherry-berry-design.md`

## Global Constraints

- License MIT; every dependency MIT/Apache-2.0/BSD/ISC/MPL-2.0 (check before adding).
- Node ≥ 22, pnpm ≥ 9, PostgreSQL 16+. Library versions: latest stable at install time.
- No user-facing AI features. No logo: the product name renders as plain text "Cherry Berry".
- Colors: primary `#8E1EA2`, accent `#C654C3`, highlight `#ED96D7`, surface-pink `#FFC0DE`, ink `#22142A`, muted `#5D4E66`, line `#E9DFEC`, surface `#FBF7FC`, success `#1E7A46`, warning `#B45309`, error `#B3261E`. Body text only in ink, muted or `#8E1EA2`.
- Fonts: Space Grotesk (headings), Inter (body).
- Workspace roles: `owner`, `admin`, `editor`, `viewer`. Access modes: `invite`, `password`, `open`.
- All server routes under `/api`. JSON errors are `{ "error": "<code>" }`.
- Windows dev machine: scripts must not rely on POSIX-only shell syntax (use `cross-env` where env vars are set in scripts).

## Review Focus

1. Guessing a workspace password repeatedly → `POST /api/workspaces/join` returns 429 after 10 attempts per minute from one IP. (Task 6)
2. Joining a workspace you already belong to → succeeds, no duplicate membership, role unchanged (an owner stays owner). (Task 5)
3. Invitation token that is expired, already used, or opened by a different email → rejected with `invitation_invalid`, `invitation_used` or `invitation_wrong_email`. (Task 5)
4. Workspace ID typed with different case or spaces (`" North-7q4k "`) → finds `north-7Q4K`. (Task 4)
5. A `.cherry` file from a newer format version → `parseCherry` returns `{ ok: false, error: "newer_version" }` instead of throwing or loading half a document. (Task 2)

### Task 5: Workspace service

**Files:**
- Create: `apps/server/src/workspaces/service.ts`, `apps/server/src/workspaces/errors.ts`
- Test: `apps/server/test/workspaces.service.test.ts`

**Interfaces:**
- Consumes: `Db`, tables and `makeWorkspacePublicId`/`normalizePublicId` (Task 4)
- Produces (all `async`, first arg `db: Db`):
  - `type Role = "owner" | "admin" | "editor" | "viewer"`; `type AccessMode = "invite" | "password" | "open"` (exported from `service.ts`)
  - `class WorkspaceError extends Error { code: "not_found" | "wrong_password" | "wrong_mode" | "password_required" | "forbidden" | "invitation_invalid" | "invitation_used" | "invitation_wrong_email" }`
  - `type WorkspaceSummary = { id: string; name: string; publicId: string; accessMode: "invite" | "password" | "open"; role?: Role }`
  - `createWorkspace(db, userId, input: { name: string; accessMode: AccessMode; password?: string }): Promise<WorkspaceSummary>` — creator becomes `owner` (`joinedVia: "created"`); `password` mode requires password length ≥ 8 else `password_required`; hash with argon2id (`@node-rs/argon2`); retry public id on unique collision up to 5 times.
  - `joinWithPassword(db, userId, publicIdInput: string, password: string): Promise<WorkspaceSummary>` — `normalizePublicId`; missing → `not_found`; mode ≠ `password` → `wrong_mode`; bad password → `wrong_password`; new member role `editor`.
  - `joinOpen(db, userId, workspaceId: string): Promise<WorkspaceSummary>` — mode ≠ `open` → `wrong_mode`; new member role `editor`.
  - `createInvitation(db, inviterId, workspaceId, input: { email: string; role: "admin" | "editor" | "viewer" }): Promise<{ token: string; expiresAt: Date }>` — inviter must be `owner` or `admin` else `forbidden`; token = 32 random bytes base64url; store sha256 hash; expires in 7 days.
  - `acceptInvitation(db, userId, userEmail: string, token: string, now?: Date): Promise<WorkspaceSummary>` — unknown or expired → `invitation_invalid`; `acceptedAt` set → `invitation_used`; email mismatch (case-insensitive) → `invitation_wrong_email`; adds member with invitation role, sets `acceptedAt`.
  - `listMyWorkspaces(db, userId): Promise<WorkspaceSummary[]>` (with `role`, ordered by name)
  - `listOpenWorkspaces(db, opts: { q?: string; limit?: number }): Promise<WorkspaceSummary[]>` — only `open` mode, `name ILIKE %q%`, default limit 20, max 50.
  - Joining when already a member (any path) returns the workspace with the **existing** role and inserts nothing (`onConflictDoNothing`).
